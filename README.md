# CivPro Practice: feedback chain, unbundled

Course-grounded feedback on Civil Procedure practice exams, built around Professor Jim Greiner's
HLS Civil Procedure course. This is the same prompt chain as the hosted CivPro Practice app,
minus the web UI, the sign-in, and the five-attempt cap. Clone it, open it in Claude Code or
Codex (or plug in your own API key), and take as many cracks at as many exams as you like.

You submit a practice answer (a whole exam or one question, as prose or bullet points). Back
comes feedback organized question by question. Every critique is anchored to a quote from your
answer, and every prescription is grounded in the course's own materials and vocabulary.

> Formative practice only. The feedback is generated by a language model. It has been tuned
> against real graded answers and reviewed by people who know the course, but it is not your
> professor and not a grade.

## Quick start

```bash
git clone https://github.com/ll-catacomb/civ-pro-feedback-public
cd civ-pro-feedback-public
npm install            # Node 22.13+
npm run exams          # list exam/assignment IDs
```

Write your answer into a file (say `my-answer.md`), then choose one of three ways to run it.

### A. In Claude Code (no API key)

```
claude
> /feedback my-answer.md 2019-final
```

Claude reads `AGENTS.md` and runs the chain one stage at a time. Each stage's prompt goes to a
fresh subagent, and the CLI checks every output against its schema. Your Claude plan pays for it.

### B. In Codex (no API key)

```
codex
> Run the feedback chain on my-answer.md for the 2019 final, following AGENTS.md.
```

Codex reads the same `AGENTS.md`. Each stage runs as its own `codex exec` session.

### C. With your own API key

```bash
cp .env.example .env          # add ANTHROPIC_API_KEY (or an OpenAI-compatible key)
npm run feedback -- --exam 2019-final --answer my-answer.md
npm run feedback -- --exam 2019-final --answer q2.md --question "Question 2"
npm run feedback -- --exam 2023-assignment-02 --answer notes.md --mode bullet_points
```

The default models are `claude-sonnet-5` for the lighter stages and `claude-opus-5-5` for the
blind evaluation and the judge, matching the hosted app. Override them in `.env`. Any
OpenAI-compatible endpoint (OpenAI, OpenRouter, a local server) works with
`CIVPRO_PROVIDER=openai`. Results won't match exactly on other models; the prompts were tuned on
Claude.

Every run writes a folder under `runs/`:

- `feedback.md` — the student-facing feedback. **Start here.**
- `audit.md` — the internal view: band estimate, per-criterion scores, judge corrections, retrieval mode, tokens.
- one JSON file per stage, plus `prompts/` (in harness mode) holding the exact prompt each stage saw.

## How it works

Eight structured-output calls, each blind to later stages and to any real grade:

| # | Stage | What it does |
|---|---|---|
| 1 | `submission_fit` | Does this answer respond to the selected exam at all? |
| 2 | `submission_fit_judge` | Independent re-check. If both say no, the chain stops at zero credit. |
| 3 | `issue_map` | Point-aware rubric built from the exam and the instructor's model answer |
| 4 | `retrieval_query` | Names the doctrine vocabulary the course materials use |
| — | BM25 (local) | Searches ~400 course files for 48 candidate excerpts |
| 5 | `retrieval_rerank` | Keeps the ≤24 excerpts that actually matter |
| 6 | `blind_evaluation` | Scores each criterion 0–4 and ranks the answer against graded references |
| 7 | `feedback_draft` | The coach: turns findings into question-by-question feedback, with each "add this" paired with a "cut that" |
| 8 | `judge_and_revise` | Skeptical pass: verifies claims and quotes, and enforces ~25 drafting rules from human reviewers |

Diagrams and the exact inputs for each stage are in [PROMPT-CHAIN.md](PROMPT-CHAIN.md). The
readable prompt text is in [prompts/](prompts/), and the source is in [`src/prompts.ts`](src/prompts.ts).

## What's in the box

- **[content/](content/README.md):** past finals (2007–2025) with Greiner's model answers, graded
  assignments with circulated exemplary answers, the casebook, class summaries, slides, primers,
  rules and statutes, and review sessions, all as cleaned Markdown.
- **[prompts/](prompts/README.md):** every stage's system prompt and output schema, readable.
  This includes the instructor-supplied course conventions ("Greinerisms", abbreviations, law
  changes since older materials, brain-off topics).
- **[docs/QA.md](docs/QA.md):** how the chain was calibrated and reviewed, and how to keep doing it.
- **[docs/prompt-feedback-log.md](docs/prompt-feedback-log.md):** eight rounds of human review.
  Each one records what reviewers flagged, what was verified, and which prompt rule it produced.

**Not included:** real students' graded final-exam answers. The hosted app used them as band
anchors. The chain runs fine without them; to restore that calibration, see
[content/graded-answers/](content/graded-answers/README.md), which explains where HLS students
can find posted answers.

## Remixing

Change anything. [AGENTS.md](AGENTS.md#editing-the-chain-remixing) maps each kind of change to
the file to edit. Bump `PROMPT_VERSION` when you change a prompt, and re-run a few answers whose
quality you already know before trusting the change ([docs/QA.md](docs/QA.md)).

New exams are a content change, not a code change. Drop a `<year>-final.md` and its model answer
into `content/course/exams/`.
